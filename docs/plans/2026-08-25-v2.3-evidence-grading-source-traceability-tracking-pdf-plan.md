## Phase 1：证据分级与置信度模型

目标：每条证据都有 `source_type`、`grade`、`confidence`，历史数据可幂等回填。

### 后端

- [x] 在 `backend/app/main.py` 增加 `EvidenceGrade`、`EvidenceConfidence`、`EvidenceRef` 模型。
- [x] `EvidenceRecord` 增加字段：
  - `source_type`
  - `grade`
  - `confidence`
  - `file_name`
  - `retrieved_at`
- [x] `EvidenceSnippet` 增加字段：
  - `grade`
  - `confidence`
  - `source_url`
  - `source_date`
  - `page_label`
- [x] `EvidenceLibrary.summary` 增加 `grade_summary`。
- [x] `EvidenceItem`（report 证据链）增加 `EvidenceRef` 兼容字段。
- [x] `ContradictionMatrixRow` 增加 `supporting_evidence_refs` / `opposing_evidence_refs`。
- [x] `TrackingDashboardItem` 增加 `evidence_refs`。

### 分级逻辑

- [x] 实现 `grade_evidence_record(item)`：

- [x] 实现 `confidence_for_evidence(item, snippet)`。
- [x] `_normalize_evidence_record` 增加幂等回填：已有等级不覆盖，缺失字段自动计算。
- [x] `summarize_evidence_library` 输出 `grade_summary`。

### 测试

## Phase 2：公告原文浏览与来源追溯增强

目标：用户能从摘要/矩阵/跟踪看板/证据链打开原始 PDF/文本，并看到页码与来源元数据。

### 后端 API

- [x] 改造 `extract_pdf_text`：按页提取文本，保存全文 `text/{evidence_id}.txt` 与分页映射 `text/{evidence_id}.pages.json`。
- [x] `build_evidence_snippets` 根据句子所在页写入真实 `page`。
- [x] 新增 `GET /api/evidence/{ticker}/{evidence_id}/pdf`：
  - 校验 ticker 与 evidence_id。
  - 校验 `local_pdf_path` 位于该 ticker 证据目录内。
  - 返回 `FileResponse`，`media_type="application/pdf"`，`inline`。
- [x] 新增 `GET /api/evidence/{ticker}/{evidence_id}/text`：
  - 支持 `page` 参数。
  - 返回文本预览、页码、来源元数据。
- [x] 新增 `GET /api/evidence/{ticker}/{evidence_id}/source`：
  - 返回完整结构化来源信息。
- [x] 增强 `evidence_detail`，返回 `grade`、`source_type`、`snippet_pages`。

### 安全

- [x] 统一封装 `_resolve_evidence_file(ticker, evidence_id, kind)`：
  - 只允许 `documents/{evidence_id}.pdf` 或 `text/{evidence_id}.txt`。
  - `evidence_id` 必须 `[0-9a-f]{64}`。
  - 拒绝路径穿越和符号链接逃逸。

### 前端

- [x] 证据库卡片显示等级徽标（A/B/C/D 不同颜色）。
- [x] 证据库卡片增加“查看原文 PDF”“查看文本”按钮。
- [x] 摘要、矩阵、跟踪看板、证据链中的证据引用渲染为可点击来源链接。
- [x] 点击来源链接打开原文详情/文本视图。

### 测试

- [x] `test_evidence_pdf_endpoint_returns_pdf`
- [x] `test_evidence_pdf_rejects_path_traversal`
- [x] `test_evidence_text_endpoint_returns_preview`
- [x] `test_evidence_source_endpoint_returns_metadata`
- [x] `test_evidence_detail_includes_grade_and_page_info`
- [x] `test_extract_pdf_text_keeps_page_boundaries`
- [x] `test_build_evidence_snippets_sets_real_page_number`

## Phase 3：跟踪触发器连接精确证据

目标：跟踪看板每一项都能落到具体证据 ID、引用句、页码、等级。

### 后端

- [x] `TrackingDashboardItem` 使用 `evidence_refs` 保存结构化证据。
- [x] 实现 `_validate_evidence_refs(report, snapshot)`：
  - evidence_id 必须存在。
  - quote 必须与 snippet/文本匹配。
  - 无效 ref 丢弃，并降级为 `data_insufficient`。
- [x] 更新 `_validate_snapshot_evidence`，对 `tracking_dashboard[].evidence_refs` 调用校验。
- [x] Fallback 生成器根据触发器关键词从证据库生成 `evidence_refs`。
- [x] 状态映射：
  - A/B 级直接支持 -> `confirmed`。
  - 仅有 C 级/间接 -> `watch`。
  - 无有效 ref -> `data_insufficient`。
  - 有明确反向证据且无正向 -> `invalidated`。

### 前端

- [x] 跟踪看板卡片展示“关联证据”列表：
  - 等级徽标、来源、日期、页码、引用句。
  - 点击打开原文。
- [x] 状态徽标与证据等级联动，避免 D 级证据显示“已验证”。

### 测试

- [x] `test_tracking_dashboard_accepts_valid_evidence_refs`
- [x] `test_tracking_dashboard_drops_invalid_evidence_refs`
- [x] `test_tracking_dashboard_fallback_builds_refs_from_snippets`
- [x] `test_tracking_dashboard_status_reflects_evidence_grade`

## Phase 4：PDF 分页与阅读体验优化

目标：导出 PDF 分页稳定，卡片不跨页断裂，离线可追溯。

### 后端 PDF

- [x] `build_research_pdf_html` 增加：
  - 封面后强制分页。
  - 主要章节 `break-before: page`。
  - `.panel`, `.card`, `.metric` 使用 `break-inside: avoid-page`。
  - 长列表容器允许跨页但单卡片不跨页。
- [x] 增加“证据来源追溯”小节，汇总 `evidence_refs`。
- [x] 增加 PDF 页脚/页码（优先 CSS margin boxes；不支持则降级方案）。
- [x] 检查中文字体、A4 边距和长标题换行。

### 前端（打印/预览）

- [x] 保持“导出 PDF”按钮不变，仍走 `/yanqing/api/research/{id}/pdf`。
- [x] 如有必要，增加打印样式以匹配 PDF 阅读体验。

### 测试

- [x] `test_pdf_html_contains_pagination_css`
- [x] `test_pdf_html_contains_source_traceability_section`
- [x] `test_pdf_html_keeps_evidence_cards_unsplittable`
- [x] 用户可选：在线导出 PDF 人工检查分页。

## 风险与注意事项

- 部署/重建容器必须经用户明确确认；本次未部署。
- 容器内测试文件当前为旧版，Phase 0 之前容器测试不能作为全绿依据。
- 证据分级是规则引擎，不是 AI 主观打分；宁可保守降级，不可高估证据。
- 所有新增 API 都继续受网关 SSO 保护，不在应用内另做登录。
- 不打印、不提交 `.env`、Token、数据目录或私有证据内容。
